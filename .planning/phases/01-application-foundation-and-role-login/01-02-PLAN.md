<objective>
Implement the database-backed authentication API for students and the seeded librarian, using HTTP-only browser-session cookies and server-side sessions.
</objective>

<phase_goal>
**As a** student or librarian, **I want to** authenticate against persisted accounts, **so that** the app can show only the workflows allowed for my role.
</phase_goal>

<tasks>
<task type="auto" tdd="true">
  <name>Task 1: Implement registration with student member ID validation</name>
  <files>server/src/db.js, server/src/auth/passwords.js, server/src/routes/auth.js, server/tests/auth.test.js</files>
  <behavior>
    - Valid student registration requires name, member ID, email, and password.
    - Duplicate email or duplicate member ID returns a 409 response.
    - Missing or badly formatted member ID returns a 400 response.
    - Successful registration creates a student user and starts a session automatically.
  </behavior>
  <action>Add user table constraints for unique email and unique member/student ID. Create password hashing helpers using a standard bcrypt package and never store plaintext passwords. Add `POST /api/auth/register` for student-only public registration. Validate required fields, normalize email, lightly format-check member ID, create the user, create a server session, and set an HTTP-only session cookie. This implements the student signup decisions from `01-CONTEXT.md` and must not create librarian accounts through public registration.</action>
  <verify>
    <automated>npm run test --workspace server -- auth.test.js</automated>
  </verify>
  <done>Student registration persists the user, rejects duplicate or invalid member IDs, and returns the newly authenticated student from the test client.</done>
</task>

<task type="auto" tdd="true">
  <name>Task 2: Implement login, current-user, and seeded librarian access</name>
  <files>server/src/auth/passwords.js, server/src/auth/sessions.js, server/src/routes/auth.js, server/src/seed.js, server/tests/auth.test.js</files>
  <behavior>
    - Seeded student and seeded librarian credentials can log in.
    - Invalid credentials return 401 without revealing whether email exists.
    - `GET /api/auth/me` returns the current user when the session cookie is valid.
    - The session cookie is HTTP-only and expires with the browser session.
  </behavior>
  <action>Implement opaque server-side sessions stored in SQLite with a random session ID, created on login and registration. Add `POST /api/auth/login` and `GET /api/auth/me`. Ensure `server/src/seed.js` creates exactly one librarian account with fixed demo credentials and one student account with fixed demo credentials. Use browser-session cookie settings by omitting `maxAge`/persistent expiry and set `httpOnly`, `sameSite: 'lax'`, and a development-safe `secure` flag conditional on environment.</action>
  <verify>
    <automated>npm run seed && npm run test --workspace server -- auth.test.js</automated>
  </verify>
  <done>Both roles can authenticate from tests, sessions are stored in SQLite, and `/api/auth/me` returns role and display identity for a valid cookie.</done>
</task>

<task type="auto" tdd="true">
  <name>Task 3: Implement logout and reusable role guards</name>
  <files>server/src/auth/sessions.js, server/src/auth/guards.js, server/src/routes/auth.js, server/src/app.js, server/tests/auth.test.js</files>
  <behavior>
    - `POST /api/auth/logout` deletes the server session.
    - Logout clears the browser cookie.
    - Protected API handlers can require an authenticated user or a specific role.
    - Unauthenticated requests receive 401 and wrong-role requests receive 403.
  </behavior>
  <action>Add logout route, session deletion helper, cookie clearing helper, and reusable Express middleware for authenticated access and role checks. Mount auth routes in `server/src/app.js`. The guards are primarily for Phase 1 route protection and must be ready for later catalog/member/loan routes without adding admin role complexity.</action>
  <verify>
    <automated>npm run test --workspace server -- auth.test.js</automated>
  </verify>
  <done>Tests prove logout invalidates sessions, clears cookies, and guard helpers distinguish unauthenticated and unauthorized requests.</done>
</task>

<threat_model>
| Threat | STRIDE | Disposition | Mitigation |
|---|---|---|---|
| Plaintext password storage | Information disclosure | mitigate | Hash passwords with bcrypt helpers before writing to SQLite. |
| Session theft through JavaScript access | Information disclosure | mitigate | Store only an opaque session ID in an HTTP-only cookie. |
| Role escalation through registration | Elevation of privilege | mitigate | Public registration always creates `student`; librarian is seed-only. |
| Session fixation | Spoofing | mitigate | Generate a new opaque session ID on every login and registration. |
</threat_model>
